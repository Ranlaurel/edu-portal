# Образовательный портал для 6 класса — план

## 1. Суть продукта

Один ученик → два предмета на старте (русский язык, математика) → структура одинаковая для всех предметов:

```
Предмет → Раздел → Тема → Урок(и) → Тест по теме → (опц.) Итоговый тест по разделу
```

Ключевое отличие от готовых решений (Учи.ру, ЯКласс и т.п.) — контент упакован под конкретную программу конкретной школы/учебника, а не общий. Раз ты уже строил content engine — это тот же паттерн: не пишешь материалы вручную, а собираешь пайплайн генерации + лёгкая проверка.

## 2. Источник программы: РЭШ закрыт, актуальная замена — «Библиотека ЦОК»

Подтверждено официальным баннером на resh.edu.ru: **с 1 июня 2026 года поддержка портала приостановлена**, редирект ведёт на «Библиотеку цифрового образовательного контента» — новая платформа **lesson.edu.ru**, тоже государственная (Минпросвещения), тоже бесплатная и без обязательной регистрации для просмотра каталога.

Структура там даже удобнее для копирования в твой продукт:
- Темы пронумерованы **сквозно по всей школьной программе** (не по классам отдельно) — тема №171 «Русский язык — государственный язык РФ» это первая тема 6 класса, потому что 1–170 занимают темы 3–5 классов. Удобно, когда будешь добавлять другие классы.
- У каждой темы урл вида `lesson.edu.ru/lesson/{uuid}`, внутри — не 3, а **5 этапов урока**: изучение нового материала → первичная проверка усвоения (диагностическая работа) → применение изученного → систематизация знаний → итоговая проверка (самостоятельная/диагностическая работа). Это точнее ложится в твою схему «урок → тест», чем моя более грубая версия по РЭШ.
- На странице каталога есть кнопка **«Экспортировать список»** — выгружает список тем по классу/предмету файлом, не нужно парсить вручную.

## 2.1. Реальный список тем 6 класса (вытащено напрямую с lesson.edu.ru)

**Математика, 6 класс** (№171–330, разделы по порядку: натуральные числа и делимость → фигуры на плоскости, симметрия → обыкновенные/десятичные дроби → отношения, пропорции, проценты → площади, периметры, углы → буквенные выражения и уравнения → положительные/отрицательные числа → координатная плоскость, диаграммы → фигуры в пространстве → итоговое повторение).

Ключевые точки программы: делимость чисел, НОД/НОК → прямые на плоскости, симметрия → обыкновенные и десятичные дроби, все действия → отношения, пропорции, проценты, масштаб → многоугольники, площади, углы → буквенные выражения, уравнения → целые числа, модуль → действия с положительными и отрицательными числами → координатная плоскость, диаграммы → объёмные фигуры (призма, пирамида, конус, цилиндр, шар) → блок итогового повторения.

**Русский язык, 6 класс** (№171–344+, разделы по порядку: повторение 5 класса → виды речи и текст → стили речи (официально-деловой, научный) → лексика → словообразование → морфология: существительное → прилагательное → числительное → местоимение → глагол).

Ключевые точки программы: повторение 5 класса (корни, приставки, ь/ъ) → текст, планы текста, типы и стили речи → лексикология и фразеология (заимствования, диалектизмы, профессионализмы, эпитет/метафора/олицетворение) → словообразование (способы образования слов, приставки ПРЕ-/ПРИ-) → имя существительное → имя прилагательное (степени сравнения, Н/НН) → имя числительное (разряды, склонение) → местоимение (разряды) → глагол (наклонения, спряжение, безличные и разноспрягаемые глаголы).

Сквозная линия развития речи (изложения части 1-3, сочинения части 1-3) идёт вперемешку с темами — в твоей системе это можно либо отдельным треком без теста, либо встраивать практику письма прямо в уроки.

**Важно:** это официальный, но общий федеральный список — конкретная школа может изучать темы в другом порядке или с другим акцентом. Сверь с дневником/тетрадью ребёнка перед генерацией контента, это экономит переделку.

## 2.2. Как получить полный список без ручного скролла

Кнопка «Экспортировать список» на lesson.edu.ru отдаёт файл со всеми темами по предмету и классу — быстрее, чем прогонять через браузерный тул каждый раз. Прогони её вручную (может потребовать пару кликов подтверждения в браузере) или через Claude Code с браузерным скиллом — займёт минут 10 на оба предмета, и дальше у тебя будет чистый список тем-заголовков для пайплайна генерации.

## 3. Механика теста после темы

- 8–12 вопросов на тему, генерируются под учебные результаты этой темы (не абстрактные, а из тех формулировок, что были в уроке)
- Форматы: single choice, multiple choice (несколько верных), возможно — заполнение пропуска (для орфографии это важнее, чем выбор варианта)
- Порог прохождения: например 70% → иначе тест предлагается пересдать с новым набором вопросов (не теми же)
- После ответа — сразу объяснение, почему верно/неверно (без этого тест бесполезен для обучения)
- Прогресс сохраняется по каждой теме: не пройдено / пройдено / нужно повторить

## 4. Архитектура (под твой стек — не изобретаем новое)

Ты уже гоняешь Python/FastAPI/SQLite на stand.rvnza.ru — используем тот же паттерн, не React SPA с нуля:

- **Backend:** FastAPI + SQLite. Модели: Subject → Section → Topic → Lesson → Quiz → Question → Option, плюс UserProgress (ученик один, но модель пусть будет готова на нескольких — вдруг появятся другие дети/классы как продукт)
- **Frontend:** серверный рендеринг (Jinja2) или лёгкий HTML/JS без фреймворка — ребёнку не нужен SPA, нужна быстрая загрузка и простая навигация по темам
- **Контент:** хранится как markdown/JSON в репозитории, а не только в БД — так его удобно версионировать и генерировать через Claude
- **Деплой:** твой VPS (stand.rvnza.ru или отдельный поддомен), тот же паттерн, что и с threads-automation

## 5. Пайплайн генерации контента (самое трудоёмкое место)

Вручную писать уроки+тесты по ~16 темам на предмет — реалистично на грани твоего времени. Предлагаю трёхшаговый пайплайн через Claude API/Code, как у тебя content engine для Threads:

1. **Скелет программы** — список тем/подтем с учебными результатами (взяты реальные, официальные названия тем из раздела 2.1 выше, дальше по каждому предмету добить до финального списка со сверкой по дневнику ребёнка)
2. **Генерация урока** — по каждой теме: объяснение простым языком + 2-3 примера + мини-практика (не тест, а тренировочные задания с ответами прямо в уроке)
3. **Генерация теста** — 8-12 вопросов с вариантами и объяснениями, отдельным промптом, с проверкой что правильный ответ реально правильный (для математики особенно — тут нужна валидация, не доверять генерации вслепую)

Твоя роль — читать и точечно править, а не писать с нуля. По 16 темам на предмет это займёт вечер-два на предмет, если пайплайн настроен.

## 6. MVP — что делаем в первую очередь

Не делай сразу два предмета параллельно — раскатай пайплайн полностью на одном (русский или математика — что ученику сейчас актуальнее в школе), проверь на живом ученике, что тесты реально работают и не бесят, потом клонируй процесс на второй предмет за день-два.

**Этап 1 (MVP):**
- БД-схема + admin-скрипт загрузки контента из markdown/JSON
- 3-4 темы одного предмета полностью: урок + тест + прогресс
- Простой личный кабинет: список тем, статус, кнопка "пройти тест"

**Этап 2:**
- Весь первый предмет (16 тем)
- Пересдача теста с новым набором вопросов
- Простая аналитика: где чаще ошибается (по темам/типам ошибок)

**Этап 3:**
- Второй предмет
- Итоговые тесты по разделам
- Опционально: адаптивность (если тема не сдана — система предлагает вернуться раньше, чем встык её попросят)

## 7. Что нужно уточнить для точности программы

- Название учебника/УМК по каждому предмету (если знаешь — программа Ладыженской и Виленкина, взятая выше, самая массовая, но в школе может быть другой автор)
- Есть ли рабочая программа школы в бумажном/pdf виде (часто выдают родителям) — сверим порядок тем и часы

## 8. Что → как → куда (конкретная реализация)

```

│   │   └── {topic_id}/
│   │       ├── lesson.md            # сгенерированный урок
│   │       └── quiz.json            # сгенерированный тест
│   └── math/
│       └── ...                      # та же структура
├── app/
│   ├── main.py                      # FastAPI entrypoint
│   ├── models.py                    # SQLAlchemy модели
│   ├── db.py
│   ├── routers/
│   │   ├── topics.py
│   │   ├── quiz.py
│   │   └── progress.py
│   ├── templates/                   # Jinja2, серверный рендер
│   │   ├── topic_list.html
│   │   ├── lesson.html
│   │   └── quiz.html
│   └── static/
├── pipeline/
│   ├── 01_import_topics.py          # topics.json → БД (Subject/Section/Topic)
│   ├── 02_generate_lesson.py        # Claude API: тема → lesson.md

```

### Схема БД (SQLite)

```
subjects       (id, name, slug)
sections       (id, subject_id, name, order)
topics         (id, section_id, source_uid, title, order)   -- source_uid = uid темы с lesson.edu.ru, для трассируемости
lessons        (id, topic_id, content_md)
questions      (id, topic_id, text, type)                   -- type: single / multi
options        (id, question_id, text, is_correct)
explanations   (id, question_id, text)                      -- почему верно/неверно
user_progress  (id, user_id, topic_id, status, best_score, attempts)
```

### Пайплайн — порядок выполнения скриптов

1. **`01_import_topics.py`** — читает `resh_6klass_temy.json` → создаёт записи Subject/Topic в БД. Разделы (Section) пока формальные — дай список тем Claude один раз и попроси сгруппировать по смысловым блокам (лексика/морфология/дроби/уравнения и т.п.), это разовая задача на полчаса
2. **`02_generate_lesson.py --topic-id N`** — title темы → промпт в Claude → `content/{subject}/{topic_id}/lesson.md`
3. **`03_generate_quiz.py --topic-id N`** — читает готовый `lesson.md` (не тему заново) → промпт в Claude → `quiz.json` с 8-12 вопросами. Важно генерировать тест из готового урока, а не параллельно с ним — иначе они разъезжаются по формулировкам
4. **`04_load_content.py`** — заливает markdown/json из `content/` в таблицы `lessons`/`questions`/`options`
5. Ручная проверка глазами 3-4 тем перед массовым прогоном — особенно математику: Claude может сгенерировать формально верный, но нелепый пример

### Куда деплоим

- Разработка — локально, Claude Code Desktop на Windows
- Прод — твой Timeweb VPS, новый поддомен (например `uchim.rvnza.ru`), тот же паттерн деплоя, что у `threads-automation`: systemd unit + nginx reverse proxy
