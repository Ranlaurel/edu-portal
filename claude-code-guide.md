# Руководство: разработка портала через Claude Code

Документ для двух ролей одновременно: что скармливать Claude Code сессия за сессией, и что делать тебе между сессиями. Работаем локально на Windows (см. предыдущий разговор), переносим на VPS в конце.

---

## Часть 1. Что подготовить заранее (один раз, до старта)

Положи в одну папку — `edu-portal-docs/` — три файла, на них будет ссылаться каждая сессия Claude Code:

1. **`edu-portal-plan.md`** — план портала (уже есть, скачан ранее): структура контента, схема БД, архитектура, пайплайн
2. **`resh_6klass_temy.json`** — список тем (уже есть, скачан ранее): 292 темы русского + 296 математики
3. **`project-brief.md`** — новый файл, три абзаца, напиши сам своими словами:
   - Кто пользователь (один ученик 6 класса, потом возможно больше)
   - Стек: Python/FastAPI/SQLite/Jinja2, без фреймворков на фронте
   - Где будет жить: сейчас локально на Windows, потом на VPS stand.rvnza.ru (или новый поддомен)

Это не бюрократия — Claude Code в каждой новой сессии не помнит предыдущие, и этот brief экономит тебе по 5 минут объяснений на старте каждой сессии.

---

## Часть 2. Порядок сессий — что просить у Claude Code

Каждый пункт — отдельная сессия (или несколько, если разрастётся). Не смешивай этапы — Claude Code работает точнее, когда задача узкая.

### Сессия 1 — разбивка тем на разделы

**Что дать:** `resh_6klass_temy.json`

**Промпт (примерно так, адаптируй под себя):**
```
Вот список тем 6 класса по русскому языку и математике (292 и 296 тем
соответственно), полученный с lesson.edu.ru. Раздели каждый список на
смысловые разделы (Section) — например для математики: "Делимость чисел",
"Дроби", "Отношения и проценты", "Уравнения" и т.д. Для каждой темы добавь
поле "section". Сохрани результат как topics_grouped.json в том же формате
плюс новое поле. Не меняй порядок и формулировки тем — только группируй.
```

**Проверка с твоей стороны:** открой результат, пробеги глазами разбивку — Claude Code может ошибиться в 2-3 пограничных темах (например, куда отнести "Обобщение по теме X"). Поправь руками, это быстрее, чем переобъяснять.

### Сессия 2 — каркас проекта

**Что дать:** `edu-portal-plan.md` (раздел 8 — там уже вся структура)

**Промпт:**
```
Разверни структуру проекта FastAPI-портала точно по разделу 8 из
edu-portal-plan.md (структура репозитория, схема БД). Работаем локально
на Windows. Создай:
- venv и requirements.txt (fastapi, uvicorn, sqlalchemy, jinja2, anthropic,
  python-multipart)
- app/models.py — SQLAlchemy-модели по схеме БД из плана
- app/db.py — подключение к SQLite
- app/main.py — пустой FastAPI-каркас, который поднимается и отвечает
  на / заглушкой
- пустые папки content/russian, content/math, pipeline/

Проверь, что uvicorn app.main:app --reload поднимается без ошибок.
```

**Проверка:** запусти сам `uvicorn app.main:app --reload`, открой `127.0.0.1:8000` в браузере — должна открыться хоть какая-то страница, пусть пустая.

### Сессия 3 — импорт тем в БД

**Что дать:** `topics_grouped.json` из сессии 1, текущий код проекта

**Промпт:**
```
Напиши pipeline/01_import_topics.py: читает topics_grouped.json, создаёт
записи Subject → Section → Topic в БД (schema уже в app/models.py).
Скрипт должен быть идемпотентным — повторный запуск не плодит дубли
(проверяй по title или по source_uid перед вставкой). После работы
выведи в консоль количество созданных Subject/Section/Topic.
```

**Проверка:** прогони скрипт, посмотри вывод в консоли. Дополнительно проверь через `sqlite3 portal.db "select count(*) from topics"` — должно быть 292+296=588.

### Сессия 4 — пилотная генерация (руками, не скриптом!)

Это самая важная сессия — здесь проверяется, тянет ли Claude вообще качественный контент для 6 класса, прежде чем автоматизировать.

**Что дать:** 3-4 конкретных названия тем (возьми из математики — там легче проверить правильность)

**Промпт:**
```
Сгенерируй урок для темы 6 класса "[название темы]" по структуре:
1. Объяснение простым языком, без сложных терминов, на понятном для
   12-летнего ребёнка уровне
2. 2-3 разобранных примера с пошаговым решением
3. Мини-практика: 2-3 задания с ответами тут же (не тест, а тренировка)

Формат — markdown. Не используй LaTeX, только обычный текст и простые
дроби вида 3/4.
```

**Проверка — это ключевое, не пропускай:** прочитай сгенерированный урок сам от начала до конца. Для математики — реши примеры сам, проверь что ответы верные. Для русского — проверь, что правила сформулированы точно, а не приблизительно. Если 3-4 темы вышли нормально — переходи дальше. Если нет — донастрой промпт здесь же, в этой сессии, пока не станет стабильно хорошо.

### Сессия 5 — генерация теста по готовому уроку

**Что дать:** готовый `lesson.md` из сессии 4 (не тему заново!)

**Промпт:**
```
Вот готовый урок [вставь lesson.md]. Сгенерируй тест из 8-10 вопросов
строго по материалу этого урока (не выходи за его рамки). Форматы:
single choice и multiple choice (несколько верных ответов).
Для каждого вопроса дай:
- текст вопроса
- варианты ответов (для multiple choice — минимум 2 верных)
- explanation — короткое объяснение, почему ответ верный/неверный

Выведи в JSON по схеме questions/options/explanations из
edu-portal-plan.md. Дважды проверь сам, что помеченный верным ответ
действительно верен, особенно в математике.
```

**Проверка:** реши тест сам, как ученик. Найди хотя бы один вопрос, где сам можешь ошибиться не глядя — если такого нет, вопросы слишком примитивны.

### Сессия 6 — автоматизация пайплайна (только после сессий 4-5 прошли проверку)

**Промпт:**
```
Теперь что мы вручную делали для 3-4 тем, оформи как два скрипта:
- pipeline/02_generate_lesson.py --topic-id N — берёт title темы из БД
  по id, дергает Claude API с промптом [вставь финальный промпт из
  сессии 4], сохраняет результат в content/{subject}/{topic_id}/lesson.md
- pipeline/03_generate_quiz.py --topic-id N — читает lesson.md,
  дергает Claude API с промптом [вставь финальный промпт из сессии 5],
  сохраняет quiz.json туда же

Добавь --all флаг для прогона по всем темам предмета с паузой между
запросами (rate limit), и логирование прогресса в консоль.
```

**Проверка:** прогони на ещё 2-3 новых темах (не тех, что проверял руками), пробегись глазами — стабильность важнее скорости на этом этапе.

### Сессия 8 — фронт

**Промпт:**
```
Сделай три Jinja2-шаблона в app/templates/:
- topic_list.html — список тем предмета с статусом (не начато/пройдено/
  нужно повторить)
- lesson.html — рендер урока (markdown → HTML) + кнопка "пройти тест"
- quiz.html — вопросы с чекбоксами/радиокнопками, кнопка "проверить",
  после отправки — результат и explanation по каждому вопросу

Без CSS-фреймворков, минимальная читаемая вёрстка, крупный шрифт
(для ребёнка на экране). Добавь роуты в app/main.py: GET /subject/
{slug}, GET /topic/{id}, GET /topic/{id}/quiz, POST /topic/{id}/quiz.
```

**Проверка:** пройди весь путь сам в браузере — от списка тем до результата теста, на тех темах, что уже прошли ручную проверку.

### Сессия 9 — массовый прогон

Только после того, как весь цикл (сессии 1-8) отработал на 3-4 темах и ты лично прогнал его как пользователь.

**Промпт:**
```
Прогони pipeline/02, 03, 04 с флагом --all на весь предмет [русский/
математика]. Логируй ошибки отдельно, не останавливай пайплайн на
одной сбойной теме.
```

**Проверка:** не читать все 292 темы подряд — но выборочно открыть 10-15 в разных разделах, особенно в математике проверить правильность ответов.

## Часть 3. Инструкция для тебя — как вести сессии

- **Одна сессия — одна задача.** Не проси одновременно "сделай схему БД и ещё сразу фронт" — Claude Code точнее работает на узкой задаче, и тебе проще проверять результат по частям.
- **Всегда начинай сессию с контекста.** Даже если работаешь в той же папке — кратко скажи, что уже сделано и что сейчас нужно. Ссылайся на `project-brief.md` и `edu-portal-plan.md`, не пересказывай их — просто укажи "смотри план, раздел N".
- **Коммить в git после каждой рабочей сессии.** Один коммит = одна сессия, если что-то в следующей пойдёт не так — легко откатиться.
- **Ручная проверка на сессиях 4-5 — не пропускай.** Это единственное место, где решается, будет ли контент реально хорошим или "формально правильным, но нелепым". Дальше всё автоматизируется на основе этих промптов, ошибка здесь размножится на 588 тем.
- **Не проси сразу генерировать всё 588 тем.** Порядок именно такой: 3-4 темы руками → автоматизация → ещё пара тем через скрипт → и только потом весь предмет. Соблазн перескочить — самый частый способ потратить вечер на переделку.
- **Для математики — лично решай сгенерированные примеры.** Claude может дать формально верную, но методически странную задачу (например, с числами, которые не встречаются в реальных учебниках 6 класса). Твой глаз здесь незаменим.
